利用者向けの設定項目、初期値、範囲、除外指定の書式は [README の「設定」](../README.ja.md#設定)を参照してください。

## 描画の担当範囲

通常のプレイヤー描画は公式 Yes Steve Model（YSM）が担当します。Epic Fight のプレイヤーパッチが `overrideRender()` を有効にしている場合、`CombatRenderInterceptor` が Epic Fight のパッチ済み描画へ渡し、通常の描画パスをキャンセルします。Epic Fight のバニラモデルデバッグモードは対象外です。

`CombatPlayerRenderer` は Epic Fight のパッチ済みレンダラー API を通じ、変換した YSM の `HumanoidMesh` を提供します。`CombatMeshResolver` は選択中のモデルとテクスチャを使用し、変換が未完了・失敗・利用不可の場合は Epic Fight の標準メッシュへフォールバックします。一人称も同じモデル解決処理を使います。

公式 YSM の難読化メンバーへのアクセスは、YSM-Mapping-API の意味的な契約とソースエイリアスを経由します。Mapping API は別途必要な依存 Mod です。任意連携は適用範囲を限定したアダプター、リフレクション、文字列ターゲットの `@Pseudo` Mixin を使用し、連携 Mod がない環境でそのクラスを通常のリンク経路へ持ち込みません。

## モデル読み込みと入力の検証

`LocalModelRepository` は公式 YSM のカタログからモデルを解決します。`ysm.json` を持つマニフェスト形式のフォルダー、`main.json`・`arm.json`・PNG テクスチャを持つフラット形式のフォルダー、`.ysm` パッケージに対応します。フォルダーの Bedrock JSON とメモリ上で復号・解析したパッケージは、共通の `ModelBundle` になります。

旧 `YSGP` V2 パッケージは `V2PackageDecoder` でチェックサムを検証し、サイズ制限付きの名前付きアセットとしてメモリ上で復号・展開します。ジオメトリ、スケール、アニメーション、プレイヤーテクスチャはフラット形式のフォルダーと同じ規則で読み込み、不足するアニメーションは公式の既定値を継承します。形式は[公式の旧版リーダー](https://github.com/YesSteveModel/LgeacyYSM/blob/1.20.1-forge/src/main/java/com/elfmcys/yesstevemodel/util/YesModelUtils.java)に基づきます。V3 は既存の `V3PackageDecoder` と `V3BinaryPackageParser` を使用します。両形式とも既存の解析済みモデルキャッシュと `GeometryTransferCodec` に接続します。V2 のキャッシュダイジェストは復号済みアセットの名前と内容から計算し、格納順序や暗号化時の乱数には依存しません。

JSON のボックス UV は、1 ピクセル未満の立方体寸法を切り捨ててテクスチャ矩形の幅・高さがゼロになる場合も、実際に面積を持つ面を保持します。この面はテクスチャの点や行を参照し、立方体そのものを非表示にはしません。面別に明示されたゼロの `uv_size` は従来どおりその面を省略します。フォルダーと V2 のソースダイジェストには修正を反映して旧キャッシュを無効化し、V3 のダイジェストと転送方式は維持します。

バンドルはジオメトリ、モデル倍率、アニメーション、コントローラー、Molang 関数ソース、宣言済みテクスチャ、および `merge_multiline_expr`・`all_cutout`・`render_layers_first` を保持します。ベーステクスチャには LabPBR のノーマル・スペキュラーテクスチャを付随させられます。

モデル関数は `files.function_path`（既定値 `functions`）またはパッケージ内の関数エントリーから読み込みます。`ModelFunctionAssets` は正規化された名前と UTF-8 ソースを検証し、関数数 4,096、1 ソース 1 MiB、合計 16 MiB に制限します。

`OfficialDefaultAnimationLibrary` は、プライマリ以外のモデルに存在しないアニメーション名を、インストール済み公式 YSM のプライマリ `default` アセットから補完します。モデル自身のクリップが優先されます。ローカルキャッシュのフィンガープリントには、関連する元データ、継承元アセット、解析プロパティを含めます。

解析・転送の境界では、パス、サイズ、要素数、階層深度、数値の許容範囲を検証してからデータを確保・受理します。不正な入力による失敗はモデル単位に隔離され、描画側のフォールバックへ進みます。元のパッケージやモデルローカル音声のバイト列は、互換 Mod のキャッシュやモデル転送には含めません。

## メッシュ変換と姿勢合成

`SkinMeshCompiler` は Bedrock のボーン変換を累積し、Epic Fight の `HumanoidMesh` 用のインデックス付き頂点データを生成します。頂点の重複除去には位置、法線、UV、ジョイント割り当てを含め、UV の継ぎ目を保持します。

`HumanoidRig` は対応するボーンの役割を Epic Fight の 20 個の人型ジョイントに割り当てます。`AuxiliaryBoneLayout` は親から子の順にモデルボーンのスキニング番号を割り当て、合計 1,000 姿勢の範囲で最大 980 個の独立したモデルボーンを扱います。人型の経路では `AllHead` を胸へ固定し、頭のスキニングは `MHead` または `Head` から開始します。

`RigBindingPlan` はジオメトリ構造から、人型の戦闘用割り当てと、接続されたモデル独自のサブツリーを分離します。条件を満たす非人型ルートや、手・Tool 系列を頭の下に持つ胴体分岐は、人型戦闘分岐と共存しながらモデル固有の階層を維持できます。構造が曖昧な場合はフォールバックの割り当てを使います。解析範囲を制限した構造判定であり、任意の動物リグを解釈する機能や利用者向けリグプロファイルではありません。

`ParallelAnimationProgram` は Epic Fight のアニメーターとは独立してモデルのアニメーションを評価します。`AuxiliaryPoseMatrices` が、その結果を最新の Epic Fight スキン行列と合成します。

| 姿勢の領域 | 合成内容 |
| --- | --- |
| Epic Fight 担当の人型 | 戦闘の主要ジョイントへ、適用可能な補助差分と可視性スケールを加算。 |
| YSM 担当の全身 | ルート、胴体、四肢、その子孫を一続きのモデル固有姿勢として評価。 |
| モデル固有サブツリー | モデル空間の階層、または外部の Epic Fight アンカー 1 個へ接続。 |
| モデル独自の手持ち物 | 必要な親系列を含め、対象の最新 Tool ジョイントへ基準を合わせる。 |

複数の姿勢領域で共有する祖先の式は 1 回だけサンプリングします。構造を保つための姿勢専用評価では、式の代入と入れ子関数のデータフローを維持しつつ、音、パーティクル、スクリプト同期出力を抑制します。

## アニメーション選択と遷移

`AutomaticAnimationSelector` はメイン、手持ち品、装備条件、状態、乗り物、乗客、ルーレットのクリップを選択します。再生は単発、ループ、最終フレーム保持、Molang のブレンドウェイト、ステップ・線形・Catmull-Rom 補間、ループ境界をまたぐ時系列順のタイムライン処理に対応します。

`MovementAnimationType` は歩行、走行、スニーク静止・移動、ジャンプ、クリエイティブ飛行、エリトラ飛行、水泳、水中静止、ほふく静止・移動、はしご静止・上昇・下降を判定します。選択状態で YSM の全身合成を使うかは、モデル所有者側で解決した表示方針に従います。pre/main/post、hold、装備、parallel の各レイヤーをまとめて評価します。

水泳、ほふく、はしごの順に状態を判定します。ほふくは描画時の歩行速度、はしごの移動方向は現在と前 tick の Y 座標を使います。はしご専用クリップは `ladder_up`・`ladder_down`・`ladder_stillness` を選択し、なければ idle へフォールバックします。

`EpicFightPoseOwnership` は、設定で有効になる移動姿勢や通常アイテムの持ち替え姿勢より戦闘アクションを優先します。エンティティ状態、実際のアニメーション、照準、アイテム使用、振り、被ダメージ、ノックダウンを考慮します。`CLIMB` の受動的な移動ロックだけでは YSM のはしご姿勢を除外しません。通常の YSM 移動へ入るときは直前の全身表示姿勢から 3 tick で補間し、Epic Fight のアクションには直ちに担当を渡します。

YSM が担当する飛行・ほふく・はしご姿勢では必要な胴体の向きを適用し、Epic Fight の水泳ピッチを重複して加えません。頭の追従はモデルが記述した軸を尊重します。水泳・水中静止は視点追従を追加せず、はしごは未記述のピッチのみ、対応する陸上・飛行状態は未記述の軸のみを補います。Epic Fight 担当アクションでは Epic Fight の向きを使用します。

自然なはしご動作は、左腕の動きを持つ YSM のはしご専用クリップが条件です。対応する HOLD レイヤーを除外し、必要に応じて不足する右腕サブツリーをミラー補完します。通常アイテムは収納し、有効な独自手持ち物は非表示にして Epic Fight 側の重複表示も抑えます。適切なはしご腕動作がないモデルは通常の HOLD 合成を使います。

YSM 担当の騎乗姿勢は全身経路を使います。YSM の乗り物描画を無効にすると、対応する乗り物・乗客クリップと乗客ロケーター補正も無効になります。任意連携の SWEM 騎乗者アニメーションは独立した表示方針です。

ルーレット再生はモデルのルート・胴体の動きを維持し、公式の再生状態に従います。プレイヤーのルーレット音声は公式 YSM が担当し、対応メイドの経路では互換 Mod のランタイムが担当します。

## Molang・コントローラー・モデルスクリプト

`ExpressionEngine` は対応する Molang 演算子、数学関数、読み取り専用のエンティティ・ワールドクエリー、および `ysm.first_order`・`ysm.second_order`・`ysm.perlin_noise` などの YSM ヘルパーを実装します。ジオメトリのない疑似ボーンも、姿勢行列を持たずに式の副作用を実行できます。

通常変数は `v.*` と `variable.*`、roaming 変数は `v.roaming.*` と `variable.roaming.*` に対応します。リモートプレイヤーには設定変数のスナップショットを同期します。対応メイドは自身のエンティティクエリーとモデル内変数を使用し、所有者の YSM 設定変数・roaming 状態は継承しません。

`DisplayedBoneQueries` は `ysm.bone_rot`・`ysm.bone_pos`・`ysm.bone_scale`・`ysm.bone_pivot_abs` 用に、完了したフレームのモデル空間スナップショットを公開します。完全一致するボーン名で前回完了姿勢を参照し、回転は度、位置はモデル記述単位です。一人称の視点変換は含めません。

`ysm.ground_speed2` は利用可能なクライアントプレイヤーコンテキストから、Mapping API 経由で公式 YSM の最終結果を読みます。コンテキストがない場合と非プレイヤーでは 0 を返します。`ysm.in_shield_block_cooldown` は単なる盾使用ではなく、同一性を確認した防御成功通知から 5 エンティティ tick を判定します。型付きエンティティ参照の `->` は参照先の読み取り専用データを公開し、スクリプトや書き込み可能な変数は公開しません。

`AnimationControllerProgram` は初期状態、順序付き遷移、クリップの重み、`on_entry`/`on_exit`、固定・曲線ブレンド、回転の最短経路ブレンド、リマップ曲線付きのフレームローカル状態変数を扱います。空の状態は循環を検査しながら、上限付きの 1 ステップ内で連続遷移できます。

`ControllerOrder` は pre-parallel、main、hold、swing、use、passenger、その他のコントローラー、parallel の順で、対応する pre/post レイヤーも含めて合成します。同一フェーズ内は名前の辞書順です。対応するトップレベルの pre/post・parallel グループは動的な接尾辞を受け付け、parallel の固定スロット 0～7 にも対応します。

`MolangScriptRuntime` は `fn.<name>` 関数と、`@player_init`・`@player_update`・`@sync`・対応する `@player_ctrl_<slot>` ハンドラーをコンパイルします。初期化、更新、待機中の同期コールバックの順に実行します。入れ子呼び出しは独立した引数フレームを積み、深度上限は 32 です。スクリプトは Molang 評価器内で動き、JVM や OS のコードとしては実行されません。

コントローラーハンドラーはアニメーションの選択・リセット、再読み込み要求、開始遷移を指定でき、対応する continue/stop/pause/bypass 状態定数を返します。モデルが記述した Bedrock コントローラーが優先され、`ysm-builtin` 状態の場合に自動プロバイダーへ委譲します。開始遷移は保存済み姿勢を補間し、再生とイベントの時計を独立して維持します。

`ysm.sync` はローカルプレイヤーが選択中のモデルから、最大 16 個の有限数値引数を送信します。`ServerScriptEvents` が送信者の選択と頻度制限を検証し、認証済みスナップショットを送信者と追跡中のクライアントへ中継します。同一性、モデル、連番、キュー、期限を検査して古いイベントを拒否し、送信者もローカルで先行実行せず応答を待ちます。

## 音・パーティクル・プレビューの分離

`ClientSoundOutput` はモデルローカル音声の参照を公式 YSM のメモリ内音声キャッシュから解決し、名前空間付き Minecraft サウンドイベントも受け付けます。クリップ・コントローラーのスコープを抜けると対応する音を停止し、無効化時に出力を消去します。一時停止・再開は Minecraft のサウンドエンジンが担当します。

`ClientParticleOutput` は `ysm.particle`・`ysm.abs_particle` と、アニメーション・コントローラーに宣言された `particle_effects` を扱います。ロケーター、事前スクリプト、アクターへの追従に対応します。状態進入に属するエフェクトは状態終了時に終了します。一般的な人型ロケーターは胴体相対の近似値を使い、不明なロケーターはエンティティ中心へフォールバックします。

`AttackAnimationSoundMixin` は Epic Fight の攻撃フェーズの振り音を、命中・衝突音とは別に処理します。変換モデルが攻撃アイテムを置き換え、有効なモデル独自攻撃音の経路を持つ場合だけフォールバック音を抑制します。それ以外は経路判定の待機上限後に元の振り音を再生します。

`InventoryRenderScope` は一致する主描画の三人称インベントリプレビューだけに適用します。ワールドとプレビューの時計、変数、コントローラー状態、ボーンクエリー、キャッシュ姿勢、遷移を分離します。プレビューのスクリプトは `ysm.rendering_in_inventory` を参照できますが、ワールドの音・パーティクル・roaming 書き込み・スクリプト同期メッセージは出力しません。

## 評価スケジュールと補助物理

`CompiledAnimationTrack` は変更されないキーフレームサンプリング配列を保持します。時刻順のトラックは二分探索し、順序が整っていない入力は記述順を維持します。評価用の作業領域ごとに、同一時刻の数値 XYZ を再利用する上限付きキャッシュを持ちます。有限時刻・複数キー・式を含まないサンプルだけが対象で、式の評価や副作用はこのキャッシュで省略しません。

`AnimationEvaluationRateLimiter` は、エンティティ・描画コンテキストごとに互換 Mod のアニメーション全体の評価頻度を制御します。`client.animationEvaluationRateLimitHz` は 30～240 Hz または `0`（無制限）です。ゲームの FPS 制限ではありません。評価間の描画では完了済み YSM 評価結果を再利用し、最新の Epic Fight ジョイントと合成します。

次回評価期限は位相を維持し、遅れて到達した期限は中間サンプルをまとめて再実行せず集約します。アニメーション時刻は評価時点までの経過時間を反映します。コンテキスト変更、アイテム変更、クリップ再開始、待機中のスクリプト同期、関連する遷移終端では即時評価が可能です。ワールド・プレビューや、互換性のない視点・姿勢担当の間で古い評価結果を共有しません。

エンティティの tick 時計がリセットされない限り、partial tick が変わってもアニメーション時計を逆行させません。状態を持つ補助フィルターは評価間で状態を維持し、経過時間と上限付きの積分ステップを使います。

頻度制限中のモデルが現在または直前の tick に描画されている場合、補助物理のモデル方向基準は次の描画が供給します。メンテナンス tick が異なる tick 専用基準を交互に入力することはありません。描画されない tick が生じた後は、同じタイムラインと物理状態のまま tick 駆動の出力更新を再開します。

ローカルプレイヤー、インベントリプレビュー、スクリプト、状態変更・出力を伴う式など、描画スレッドを必要とする経路は同期評価します。条件を満たす副作用のないリモートプレイヤー・メイドの姿勢処理は、変更不能な `SnapshotExpressionEnvironment` を使って上限付きデーモンプールで実行します。実行待ちはランタイム状態ごとに 1 件で、描画には直前の完了結果を利用できます。

対象となるリモート処理には、距離によるスケジュール制限も適用します。

| カメラからの距離 | 最小実行間隔 |
| --- | --- |
| 16 ブロック以下 | 距離による追加間隔なし |
| 16 超～32 ブロック | 1 tick |
| 32 超～64 ブロック | 2 tick |
| 64 ブロック超 | 4 tick |

設定による評価頻度制限とリモートの距離制限は独立しています。`0` が無効にするのは設定可能な評価頻度制限だけです。

## 手持ち品と装備

`CustomHeldItemPolicy` はモデル ID の許可リストではなく、ジオメトリの可視性と hold/use/swing の意味から独自手持ち物を判定します。描画可能な手持ち物を表示する、またはその物を動かしながら Tool ロケーターを隠す記述を置き換えと判断します。エフェクトだけの弓ジオメトリは、通常の弓を置き換えずに追加できます。

`PatchedItemInHandLayerMixin` は、正確な変換メッシュの描画範囲内で、置き換え対象の手だけを抑制します。独自手持ち物は対象の Tool アタッチメントとアイテム補正に従います。検出した独自弓はモデル固有の右手規約を維持し、引き・リリースに全身姿勢を使い、保存した最終姿勢から復帰を補間します。

通常アイテムは Epic Fight のアイテムレイヤーに残ります。独立設定の YSM 持ち替えアニメーションが一時的に main/hold/controller 姿勢を合成し、アイテムの取り付け位置を更新します。戦闘アクションや別の全身担当が生じると、その遷移をキャンセルします。YSM 移動中の HOLD 合成では、その HOLD クリップのタイムラインを出力せず通常アイテムの位置を合わせられます。

`HandLocatorSelection` は三人称で、モデル固有形態の口・足・尾などに配置された Tool アタッチメントを扱います。可視かつ潰れていない候補が正確に 1 個必要です。曖昧・不正な候補では上書きせず、全候補が非表示の場合はアイテムを抑制します。論理的な左右の手への対応とアイテム単位のスコープにより、両手用レンダラーが反対の手の取り付け位置を動かすことを防ぎます。

Epic Fight のアクション中は、アイテムを描く間だけ Tool の位置を表示中の手に合わせ、Tool アニメーションの回転・拡縮・独立した動きを維持します。レイヤーから渡された姿勢を使うレンダラーと、スキンメッシュを持つアドオン武器などアーマチュアを読み直すレンダラーは、同じ一時的な姿勢を参照します。この姿勢の適用はアイテム描画とともに終了し、Tool 以外のジョイントは維持され、モデル固有形態の取り付け位置が優先されます。

変換したプレイヤーメッシュでは、防具と頭装備のレイヤーを抑制します。`ConvertedElytraLayer` は利用可能で一意な `ElytraLocator` にエリトラを描画し、それ以外では非表示にします。マント、矢、蜂の針、通常手持ち品は Epic Fight のパッチ済みレイヤーを使用します。非アクション時と YSM 担当の全身アクション時は表示中の骨格へ追従し、Epic Fight 担当アクションでは、適用範囲を限定した手持ち品の Tool 経路を除いて Epic Fight の取り付け姿勢を使います。

一人称では変換メッシュの部位可視性を使用し、人型防具パスを抑制します。変換フォールバックで Epic Fight の標準メッシュを使う場合は、通常の装備レイヤーを維持します。

## テクスチャ・マテリアル・スキニング

`OfficialTextureResolver` は、公式 YSM が選択したメモリ内テクスチャ位置を優先します。`CombatMeshCache` はエンコード済みフォールバック元を保持し、公式の位置が利用できない場合に別スレッドでデコードして、上限付きの描画スレッド GPU 登録キューへ渡します。公式テクスチャを採用すると、元データは残したまま重複した GPU 登録だけを解放します。

大文字・小文字を区別した `ysmGlow*` ボーンに直接属するジオメトリは、独立した最大光量サブメッシュになります。子孫はこのマーカーを自動継承しません。ベースと発光ジオメトリは同じアニメーション、可視性、テクスチャ、マテリアル選択を使います。

`all_cutout` は、対応する本体 RenderType の背面カリングだけを変更し、シェーダー、透過、ソートなどのマテリアル状態を維持します。輪郭や未対応の拡張 RenderType は自身の状態を維持します。`render_layers_first` は最終取り付け姿勢の公開後、本体ジオメトリより先に三人称レイヤーを 1 回描画します。変更不能な描画スナップショットで、入れ子のレイヤー描画から外側の姿勢を保護します。

`CompatHumanoidMesh` は Epic Fight の現在の compute スキニング設定と利用可能な compute 処理を使用します。実際に合成した姿勢数と、ベース・発光それぞれのサブメッシュ部位数の合計を、Epic Fight のパレット容量と照合します。両サブメッシュは同じ容量判定に従います。compute 経路が利用不可または容量超過なら、Epic Fight の三角形ベースの CPU スキニングへフォールバックします。

任意連携の `OculusPbrBridge` は、対応する Iris PBR API 名前空間を使い、Oculus に `CompatPbrTexture` 用ローダーを登録します。シェーダーのテクスチャ再読み込み後にノーマル・スペキュラーテクスチャを再生成できます。API 不在、ローダー失敗、付随テクスチャの不備があっても、ベーステクスチャは利用できます。

## 選択状態と表示方針の同期

`PlayerSelectionNbt` は、シリアライズされたプレイヤー capability データから公式 YSM のモデル・テクスチャ選択を読みます。統合サーバーではサーバープレイヤーを直接解決し、専用サーバーでは `SelectionBroadcaster` が対応クライアントへ選択更新を送ります。このメッセージは識別子だけを運び、モデル本体は含みません。

プレイヤーのモデル別ルールは所有者のクライアントで解決します。互換 Mod の通信は、手ごとの置き換え・持ち替え判定と、移動・Mod アニメーションの担当判定を送り、所有者の設定値や除外テーブルは送りません。移動メッセージには意味的な状態を含め、任意 Mod の許可判定には正確なクリップ系列と名前を含めます。

独自の飛翔体、釣り針、乗り物のジオメトリは公式 YSM が描画します。適用範囲を限定した描画ゲートが Epic Fight 戦闘モード中の採用可否を決め、戦闘モード外では変更しません。乗客ロケーターのゲートも乗り物の判定に従います。

通常保持時の置き換えを持つモデル独自の弓・トライデントは、飛翔体にも手持ち品の方針を使用します。それ以外の飛翔体専用ジオメトリとクロスボウの飛翔体は、飛翔体の方針を使用します。釣り針は釣り竿の手持ち品方針、乗り物は独立した方針に従います。

サーバーは飛翔体の発射時に、所有者、モデル、元アイテム、エンティティ種別を記録します。乗り物は現在の最初のプレイヤー乗客に従います。`SubEntityPreferenceBroadcaster` は所有者へルール解決を要求し、所有者の epoch と元状態のリビジョンで応答を認証します。戦闘モード中の判定が不明・古い場合は Epic Fight またはバニラの描画へ戻します。

所有者がいる対応メイドでは、サーバーがメイドの現在状態に対する手持ち品・持ち替えと移動の判定を、所有者へ個別に問い合わせます。独立した epoch と元状態のフィンガープリントで各通信を分離します。所有者不在や不正・古い応答では、YSM による置き換えや移動姿勢の担当を許可しません。

## サーバーからのモデル転送

選択モデルを持たないクライアントは、オンラインプレイヤーまたは同期対象の対応メイドについて、専用サーバーへ要求できます。`ServerModelTransfers` は処理前と配送前の両方で、元エンティティの ID/UUID、追跡関係、現在の選択を確認します。解析・エンコードはサーバー tick の外で行い、要求数、待機処理、受信者ごとのデータ量を制限します。

`GeometryTransferCodec` は、圧縮したジオメトリ、倍率・描画プロパティ、アニメーション・コントローラー、Molang 関数、音・パーティクルの参照、宣言済みベース・PBR テクスチャを送ります。元のパッケージやモデルローカル音声のバイト列は含みません。

クライアントは、チャンク数、同時組み立て数、サイズ、期限、SHA-256、展開後の上限を検証してからバンドルを受理します。元アニメーションの無限の長さ指定は 0 として符号化し、有効長は保持したキーから導出できます。ネットワークのデコードでは非有限値を拒否します。

要求にはリモートキャッシュのペイロード SHA-256 を含められます。応答は `DATA`・`UNCHANGED`・`UNAVAILABLE` です。`UNCHANGED` は現在のサーバー名前空間内で一致するキャッシュだけを許可し、利用できないエントリーには全体の再要求が必要です。

## キャッシュとライフサイクル

`CombatMeshCache` は上限付きワーカープールで必要になったモデルを変換します。メモリ層は完成メッシュ、エンコード済みフォールバック元、アニメーションランタイムをセッション内で保持し、GPU リソースもそのライフサイクルに従います。解析済みモデルペイロードは別途永続化できます。メモリ保持は設定可能なモデル数目標に従い、追い出し時に対応リソースを解放します。変換失敗は元データが変化したときに再判定します。

永続データは `config/ysm_epicfight_compat/cache` 以下で分離します。

| ディレクトリ | 内容と再利用条件 |
| --- | --- |
| `client` | 元データの内容で検証した、ローカル解析済みモデルペイロード。 |
| `remote` | サーバー単位で分離し、サーバーのダイジェストで再検証するリモートペイロード。 |
| `server` | サーバー側の元データで検証する、生成済み転送ペイロード。 |

ファイル名はハッシュ化し、整合性ダイジェストと圧縮ペイロードを含む、バージョン付きバイナリエンベロープを使います。テクスチャはその内部に含め、単体 PNG・JSON・パッケージとして保存しません。これらのキャッシュは整合性を検査するもので、暗号化や DRM ではありません。

各永続層には独立した容量上限と LRU 追い出しがあります。有効なキャッシュの容量が 0 の場合、ディスクを読み書きせず、メンテナンス時にエントリーを削除します。サーバー永続化を無効にすると、そのディスク層をファイル削除なしで迂回し、セッションキャッシュと同時モデル要求の集約は維持します。上限を超えるエントリーもメモリ上では使用できます。

書き込みは一時的な通常ファイルを使い、対応環境ではアトミックに置き換えます。キャッシュパスはシンボリックリンクを拒否し、破損エントリーは削除します。モデル本体の解析、内容のハッシュ、デコード、キャッシュメンテナンスはワーカー経路で処理します。処理開始時には元データの存在確認や再試行用メタデータ確認も行うため、呼び出し側スレッドからファイルシステムへのアクセスが完全になくなるわけではありません。

リソース・モデルの再読み込みとセッション終了では、対象の選択、メッシュ、テクスチャ、アニメーション、転送中状態を無効化します。世代の照合で遅れて完了したワーカー結果を拒否します。有効な永続エントリーは、通常の再利用検証に従って扱います。

## 任意アダプターとクライアント UI

| 連携 | 実装範囲 |
| --- | --- |
| Touhou Little Maid + EpicFight_TouhouLittleMaid | 両 Mod がある場合にメイドアダプターが有効になります。登録済みメイドの公開同期済み YSM 選択を参照し、メッシュの置き換えは EFTLM のパッチ済み描画内に限定します。変換が利用できない場合は EFTLM のメッシュを維持します。 |
| ParCool | プレイヤーの対応するネイティブアクション状態・時計を、アニメーターを進めずに参照し、利用可能な `parcool:*` モデルクリップを選びます。 |
| Epic ParCool | 特定の Chain movement・Wall movement アニメーションを優先し、その姿勢の担当を維持します。 |
| SWEM | 生存する SWEM 馬へ直接騎乗しているプレイヤーのアクティブな騎乗者アニメーションレイヤーを参照し、利用可能な `swem:*` クリップを選びます。 |
| Oculus（Iris PBR API） | 前述のフォールバックテクスチャ用 LabPBR ブリッジを提供します。 |
| Configured | 動的な除外テーブル編集とアニメーション評価頻度スライダーを提供します。画面がなくても TOML 設定は機能します。 |

メイドアダプターは EFTLM の `0.8` 倍率をメッシュ内だけの `1.25` 倍率で補正し、変換描画後に手持ち品の平行移動も合わせます。リターゲットでは拡張専用のアーマチュアサブツリーへ変換済み人型番号を割り当てず、不正に重なる拡張を拒否します。装備レイヤーは EFTLM が維持します。

ParCool・SWEM アダプターはリモートを含むプレイヤーだけに適用します。一致する利用可能なモデルクリップと所有者の許可が必要です。ネイティブの時計・再開始識別情報を再生に使用し、SWEM 騎乗は古い ParCool 状態より優先します。変更するのは表示姿勢であり、移動、当たり判定、ゲームプレイ用アーマチュア、馬のレンダラーではありません。Epic Fight の戦闘アクションや、より優先度の高いモデル独自アクションは担当を維持します。

`ClientPreferences` がクライアント内の外観と評価方針を、`ServerPreferences` が別の common ファイルにあるサーバーキャッシュ設定を担当します。Configured のスライダーは 30～240 Hz と右端の無制限で構成し、無制限は `0` として保存します。除外編集では選択モデルの編集行を追加し、空行は保存しません。

`CombatOverlayPolicy` は戦闘モード中に設定どおりの YSM オーバーレイ表示を適用します。`YSMCompatibilityWarningState` は公式 YSM の Epic Fight 警告への確認を記録し、無関係な警告は抑制しません。`ClosingScreenClickPolicy` は、画面を閉じた未処理クリックがゲーム操作へ届く前に消費します。

## 対応範囲と検証

描画の対象は公式 YSM のプレイヤーモデルと明示的なメイドアダプターです。モデルの各機能を再現できるかは、実装済み Molang・クエリー・コントローラーの範囲、リグ解析、パーティクルロケーター、装備規則、任意 API の境界に従います。モデル機能や任意 API が不足する場合は、すべてのモデルで同一の表示を保証するのではなく、記述したフォールバック経路を使います。

コンパイル、自動テスト、配布物検証が確認するのは、それぞれのコード・パッケージ上の性質です。実ゲームの結果を保証するものではなく、アニメーションの見た目、一人称、装備、シェーダー、再読み込み、マルチプレイにはゲーム内確認が必要です。
